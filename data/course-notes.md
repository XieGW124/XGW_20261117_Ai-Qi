# 课程资料：Web 前端与 Node.js 应用开发

本文件是 AI 答疑助手的课程资料库。助手会先检索这里的段落，再把相关内容和学生问题一起交给大模型。

## 课程说明

本课程面向具备基础编程能力的同学，内容覆盖 JavaScript 核心机制、异步编程、Node.js 服务端开发，以及大模型应用的工程实践。学习建议：每节课后先复现代码示例，再尝试独立完成一个小练习；遇到问题时先描述清楚“现象、预期、已尝试的方法”，再去提问，效率会更高。

## 1.1 变量与作用域

JavaScript 使用 let、const 和 var 声明变量。let 与 const 具有块级作用域，var 是函数作用域并且存在变量提升。const 只保证绑定不被重新赋值，并不代表对象内容不可修改。优先使用 const，需要重新赋值时使用 let，尽量避免 var。

作用域链决定了变量的查找顺序：内层作用域可以访问外层作用域的变量，外层作用域不能访问内层作用域的变量。

## 1.2 闭包

闭包是指函数与其词法作用域的组合。当一个内部函数引用了外部函数的变量，并且这个内部函数在外部函数返回后仍然被使用，就形成了闭包。

闭包的典型用途包括：封装私有变量、实现函数工厂、保存异步回调需要的数据。使用闭包时要注意，被引用的变量不会被垃圾回收，长生命周期的大对象可能造成内存占用升高。

示例：

```js
function createCounter() {
  let count = 0;
  return function () {
    count += 1;
    return count;
  };
}
const counter = createCounter();
counter(); // 1
counter(); // 2
```

## 1.3 原型与原型链

每个对象都有一个内部属性指向它的原型对象。访问对象属性时，如果自身没有该属性，JavaScript 会沿着原型链向上查找，直到找到属性或者到达原型链终点 null。

构造函数的 prototype 属性就是实例对象的原型。ES6 的 class 本质上也是基于原型的语法糖。判断属性是否属于对象自身应使用 Object.prototype.hasOwnProperty，in 运算符则会检查整条原型链。

## 1.4 this 指向

this 的指向取决于函数的调用方式：普通函数调用时，非严格模式下指向全局对象，严格模式下是 undefined；作为对象方法调用时指向该对象；通过 call、apply、bind 可以显式指定。箭头函数没有自己的 this，它会捕获定义时所在外层作用域的 this。

## 1.5 事件循环

JavaScript 是单线程执行模型，依靠事件循环调度任务。同步代码最先执行，然后依次清空微任务队列（Promise 回调、queueMicrotask），再取一个宏任务（setTimeout、setInterval、I/O 回调）执行，重复这个过程。

因此 Promise.then 中的回调会先于 setTimeout 回调执行。理解事件循环有助于分析异步代码的执行顺序，避免写出依赖不确定时序的逻辑。

## 2.1 Promise

Promise 表示一个异步操作的最终结果，有三种状态：pending、fulfilled、rejected。状态一旦改变就不能再变。Promise 可以通过 then 注册成功回调，通过 catch 处理失败，通过 finally 执行收尾逻辑。

Promise.all 等待全部成功，任意一个失败就整体失败；Promise.allSettled 会等待全部完成并返回每个任务的状态；Promise.race 返回最先完成的任务结果。

## 2.2 async/await

async 函数总是返回 Promise。在 async 函数内部使用 await 可以等待 Promise 完成，写法更接近同步代码。await 后面的表达式如果不是 Promise，会被自动包装成 resolved 状态的 Promise。

多个互不依赖的异步任务应并行发起，例如先创建全部 Promise，再用 Promise.all 等待，避免用多个 await 串行执行导致总耗时叠加。

## 2.3 错误处理

异步错误需要使用 try/catch 或 Promise 的 catch 捕获。未捕获的 Promise 拒绝会导致进程告警甚至退出。对于网络请求，要区分业务错误与网络错误，并在超时、连接失败、返回内容为空等情况下给出明确的错误提示。

## 3.1 原生 http 模块

Node.js 内置的 http 模块可以直接创建 HTTP 服务，不需要任何第三方框架。基本流程是：调用 http.createServer 传入请求处理函数，在函数中读取 req 的方法、路径和请求体，最后通过 res.writeHead 设置状态码和响应头，再用 res.end 返回内容。

解析请求体时需要监听 req 的 data 事件收集 Buffer，监听 end 事件后拼装并解析 JSON。为防止恶意大请求，应设置请求体大小上限。

## 3.2 路由与静态资源

没有框架时，路由可以基于 req.url 和 req.method 手动分发，例如 /api/ask 交给接口处理，其余路径交给静态资源处理。

静态资源服务要用 path.resolve 计算真实文件路径，并校验结果必须位于 public 目录内，防止通过 ../ 进行目录穿越。同时根据文件扩展名设置正确的 Content-Type，例如 .html、.css、.js、.png。

## 3.3 环境变量

Node.js 通过 process.env 读取环境变量，适合存放密钥、接口地址、模型名称等部署相关配置。代码中应为缺失的变量提供默认值，但密钥类配置不应有默认值，缺失时应进入降级逻辑。

不要把真实密钥写进代码或提交到 Git 仓库。运行服务时可以在命令行前设置环境变量，也可以使用 Node.js 的 --env-file 参数加载本地文件。

## 4.1 OpenAI 兼容接口

兼容 OpenAI 协议的服务通常提供 POST /chat/completions 接口，请求体包含 model 和 messages，messages 是由 role 和 content 组成的数组，role 可以是 system、user、assistant。

请求头需要 Content-Type: application/json 和 Authorization: Bearer <API_KEY>。返回结果中，回答文本位于 choices[0].message.content，token 用量位于 usage 字段。

## 4.2 提示词设计

提示词应明确角色、任务、约束和输出格式。答疑场景下，可以在 system 消息中限定“优先依据课程资料回答”“资料不足时说明是补充内容”“使用中文分点作答”，从而减少编造和跑题。

把检索到的资料放在 user 消息中，并用清晰的分隔标记，例如“课程资料：”“学生问题：”，有助于模型区分资料与问题。

## 4.3 检索增强生成（RAG）

检索增强生成的基本流程是：把资料切分成段落，对问题和段落分别分词或向量化，计算相关度并选出 Top N 段落，再把这些段落和问题一起交给大模型。

不引入向量数据库时，可以使用关键词重合度做轻量检索：中文按二元组分词，英文按单词切分，过滤停顿词，再按命中词频和标题加权排序。这种方式实现简单、可解释性好，适合课程项目。

## 4.4 超时与异常处理

调用大模型必须设置超时，否则网络异常时请求可能长时间挂起。Node.js 原生 fetch 可以配合 AbortController 和 setTimeout 实现超时中断，请求结束后要清理定时器。

异常处理需要覆盖：网络连接失败、接口返回非 2xx 状态码、返回内容不是合法 JSON、choices 为空、回答文本为空。其中“返回文本为空”应按失败处理，不能当作成功结果返回给用户。

## 5.1 常见问题：如何调试接口

可以使用浏览器开发者工具的 Network 面板查看请求和响应，也可以使用 curl 或 PowerShell 的 Invoke-RestMethod 直接请求接口。服务端应打印必要的日志，但不要输出密钥等敏感信息。

## 5.2 常见问题：页面请求失败

如果前端请求 /api/ask 返回 404，先检查服务端路由是否注册了该路径；如果返回 500，查看服务端日志中的异常信息；如果浏览器控制台提示跨域错误，说明页面与接口的协议、域名或端口不一致，开发阶段建议由同一个 Node.js 服务同时提供页面和接口。

## 5.3 常见问题：如何准备演示

演示前确认 Node.js 版本不低于 18，因为需要内置 fetch。未配置 LLM_API_KEY 时服务会自动进入演示模式，返回预设回答，便于在没有网络或没有密钥的环境下完整走通“检索资料、生成回答、保存记录”的流程。
